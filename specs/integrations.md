# Граница корпоративного подключения

Транспорт не даёт дополнительных прав. Реальный Jira/Confluence или MCP-сервер подключается через адаптер к тем же проверкам. Встроенный HTTP-сервис остаётся имитацией; настоящие подключения требуют согласованных адресов, учётных данных и проверки в целевой среде.

## Идентичность

Локальный режим `demo` допускает только синтетический каталог и выбор профиля. Режим `corporate` отключает выбор профиля и демонстрационные события. Вход выполняется через существующий OIDC-провайдер: authorization code, PKCE, одноразовый state с привязкой к cookie, nonce, проверка подписи, issuer, audience и срока ID token. ID token не используется как токен корпоративного API.

Доверенный каталог связывает пару issuer/subject с внутренним ID. Пользовательский текст, email, отображаемое имя и параметры callback не назначают команду или права. Неизвестная идентичность получает отказ. Сессия не живёт дольше подтверждённой идентичности. Секрет клиента и промежуточный PKCE verifier остаются на сервере.

Корпоративные cookies имеют префикс `__Host-`, Secure, HttpOnly и Path=/; соседний поддомен не может подставить cookie другого аккаунта. Сессия привязана к доверенному профилю и перестаёт действовать после изменения команды, роли или идентичности. Внутренний ID закрепляется за одной парой issuer/subject; назначить его другому человеку или автоматически присвоить старую демо-историю нельзя. Перед чтением личных данных проверяется также актуальное право `read` на `ai-buddy/account/<id>`.

## Ресурсы и операции

У защищённого источника задан точный ресурс: система, тип и ID. Корпоративный режим требует отдельного сервиса авторизации. Проверяются конкретные `read`, `request_access`, `assign_self`; неизвестное действие запрещено. Решение привязано к субъекту, ресурсу и действию, имеет результат и версию политики. Ошибка, неполный или не совпадающий ответ означает отказ. Проверка повторяется перед исполнением и выдачей сохранённого ответа.

Сервисный токен приложения не является пользовательским токеном. Рабочий адаптер не содержит методов выдачи демонстрационных событий. При отсутствии идемпотентности внешнего API нужен поиск результата по устойчивому ключу перед повторной отправкой; сам HTTP/MCP не обеспечивает эту гарантию.

Подтверждённое решение назначенного владельца проходит через `ResourceDecider` и
`POST /decisions` сервисного адаптера. Это отдельный контракт от `DemoOperator`:
проверяются текущий участник, версия карточки, точное пространство и разрешение
`decide_access`. Имитация повторно проверяет владельца и переход. Сохранённое
намерение предотвращает два разных решения по одной версии; потерянный результат
восстанавливается чтением операции. Реальный коннектор обязан реализовать этот
контракт и авторизацию в целевой системе; простой перенос токена недостаточен.

## Контекст модели

Документы имеют явную классификацию `public` или `internal`; неизвестное значение считается внутренним. `ALLOW_EXTERNAL_MODEL` разрешает адрес, но не передачу данных. Для внешней модели нужны политика `public-only` и подтверждение конкретного вопроса пользователем. Передаются только публичные источники; история, имя команды, внутренние ID и служебные зависимости не передаются. При наличии внутреннего источника запрос останавливается без переключения провайдера. Проверка секретного ввода применяется также к вопросу и материалам; она не является универсальной DLP.

## Аудит

Отдельный журнал хранит время, инициатора, владельца контекста, действие, объект, решение и результат, корреляционный ID и длительность. Успех операции записывается вместе с результатом; отказы и неизвестный исход также фиксируются. Текст вопроса, документы, cookie и ключи в журнал не включаются. Смена статуса сохраняет историю переходов с оператором, а не только последнее значение.

В корпоративном режиме приложение не выполняет DDL. Схему применяет отдельная роль миграций; runtime получает INSERT/SELECT для журнала без UPDATE/DELETE. Защита журнала от администратора БД этим не заявляется. Удаление старых данных и срок хранения определяются политикой эксплуатации; записи PKCE очищаются после истечения при следующем входе.

## Проверки

| Проверка | Ожидаемое поведение |
| --- | --- |
| Чужой/истёкший/поддельный OIDC token, неверный state или nonce, повтор callback | Отказ без сессии |
| Изменённый profile_id в корпоративном режиме | Демо-вход недоступен |
| Разрешён один документ, другой ресурс той же команды закрыт | Второй не попадает в поиск, контекст или историю |
| Авторизация недоступна либо решение относится к другому объекту | Закрытая операция не выполняется |
| Новые параметры, повтор подтверждения, потерянный ответ | Точное подтверждение и один сохранённый результат |
| Внешняя модель без подтверждения либо с внутренним контекстом | Сетевого запроса к модели нет |
| Отказ, неизвестный исход, повтор или операторское событие | В журнале есть действующий субъект и результат без текстов/секретов |

MCP пока не заявляется реализованным. Для него дополнительно проверяются доверенный сервер, список разрешённых инструментов, схемы аргументов/результатов, audience и scopes токена; пользовательский токен не пересылается другому API. Протокольная проверка обязательна перед заявлением поддержки.
