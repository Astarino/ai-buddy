# Гибридный поиск

Сервер сначала проверяет команду, направление и ACL документов. Только разрешённые
снимки передаются локальному поиску и embedding-сервису. Документ разбивается на
фрагменты до 700 символов с перекрытием 100; результат сохраняет ID, происхождение,
версию и полный отпечаток исходного документа. Контекст ответа — до трёх фрагментов.

BM25 (k1=1.2, b=0.75) и cosine embeddings ранжируются отдельно. RRF (k=60)
объединяет позиции; дубли одного документа удаляются. EmbeddingGemma 300M
используется локально, модель и digest закрепляются конфигурацией. Векторный кеш
хранится локально с правами 0600; ключ включает модель и отпечаток снимка.
Изменение и удаление документов исключает старые записи при следующем запросе;
после перезапуска индекс может быть построен заново из разрешённых снимков.

При ошибке или отсутствии embeddings поиск возвращает BM25 с явным статусом
`bm25_fallback`. Это не переключает LLM. Нет ответа и неизвестные сведения
требуют уточнения. Ни имя, ни фрагмент закрытого источника не выдаются.

Given запрещённый документ, then он отсутствует во всех четырёх вариантах поиска.
Given обновление/удаление, then прежний вектор не используется.
Given отключённый embedding-сервис, then доступные лексические результаты остаются.
Given несовпадающая размерность/NaN/нулевой вектор, then используется безопасный fallback.

Качество сравнивается на 20–30 фиксированных вопросах: baseline, BM25, embeddings,
hybrid, Recall@5, MRR@10 и задержка. Нет ответа и запрет учитываются отдельно;
метрики поиска не доказывают правильность сгенерированного ответа.
