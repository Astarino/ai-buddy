# AI Buddy: поведение продукта

Статус: спецификация первой версии, 11.11.2026. AI Buddy предназначен для стажёров разных направлений. Первая версия проверяет сценарии первых двух недель на Backend-примере из кейса; поддержка остальных направлений ещё не проверена. Названия команд, люди, рабочие инструкции и результаты корпоративных сервисов синтетические.

Вопросы стажёра не ограничиваются пунктами чек-листа. Чек-лист — один из источников маршрута; помощь также может относиться к рабочей задаче, процессу, инструменту или поиску нужного контакта. Ответ требует применимых разрешённых источников; при нехватке информации действуют уточнение и обращение к наставнику. Направление и команда определяют содержание помощи, но не расширяют полномочия модели.

## Результат для стажёра

Разобраться с препятствием, получить доступ к материалам команды, изучить руководство и взять первую подходящую задачу. Точка входа — личный диалог. Маршрут и источники дополняют его. Веб-клиент воспроизводит этот способ работы; подключение к настоящему Mattermost не заявляется.

## Сценарии приёмки

| S01 | У стажёра нет доступа к пространству. При входе видны следующий шаг, зависимости, команда и наставник. | domain, UI, e2e |
| S02 | Стажёр спрашивает о проблеме с доступом. Buddy использует разрешённую инструкцию, предлагает конкретный ресурс своей команды, не читает закрытое руководство. | retrieval, chat, e2e |

| S05 | Повтор подтверждения или потерянный ответ не создаёт вторую операцию. Проверяется результат по тому же ключу. | integration |

| S07 | Во время ожидания доступны независимые задачи. Отказ не завершает получение доступа. Техническая ошибка не превращается в отказ. | domain, UI |
| S08 | Стажёр открывает руководство и сам отмечает изучение. Только после этого можно подготовить взятие первой задачи. | domain, e2e |
| S09 | Подтверждённое взятие задачи возвращает её ключ, назначенного исполнителя и статус. Завершение рабочей задачи подтверждает сервис, не текст модели. | integration, e2e |
| S10 | Вопрос по источникам получает короткий ответ с открываемыми документами и происхождением. Другие команды и закрытые документы исключены до модели. | retrieval, model |
| S11 | Нет надёжного ответа или источники противоречат друг другу. Buddy уточняет и позволяет подготовить черновик вопроса наставнику. Автоматической отправки нет. | chat, UI |
| S12 | Запрос другой роли, чужого действия, документа или операции не раскрывает их. Текст «я руководитель» не меняет доверенный контекст. | security |
| S13 | Модель недоступна, вернула неправильный формат или тайм-аут. Интерфейс доступен, ошибка явная, повтор возможен, внешнего fallback нет. | model, UI |
| S14 | Права отозваны. Повторное чтение, поиск и сохранённые ответы по закрытому источнику больше не раскрывают текст. | security |
| S15 | Два тестовых пользователя имеют независимые диалоги, маршруты и заявки, включая две вкладки браузера. | session, integration |
| S16 | После отзыва доступа повтор прежнего ID сообщения не возвращает закрытый ответ. | security, HTTP |
| S17 | Во время генерации отозван доступ; модель вернула закрытый текст с пустыми или публичными цитатами. Сервер не выдаёт ответ. | security |
| S18 | Запрос о секрете заблокирован. Следующий обычный вопрос не передаёт заблокированный ввод в модель. | security, model |
| S19 | Интеграция вернула 307/308 на другой адрес. Тело и ключи не пересылаются, операция не объявляется успешной. | transport |
| S20 | Источник имеет неизвестный Scope или право другого ресурса. Чтение и поиск запрещены. | security |
| S21 | Изменены параметры подготовленного действия. Нужна новая карточка; прежняя не отправляется. | actions, UI |
| S22 | Вопрос вне чек-листа или другого направления получает применимый ответ либо уточнение. GitHub 403 не создаёт запрос к вики. | retrieval, chat |

## Маршрут и сроки

Маршрут содержит 12 шагов первой и второй недели. Пункты заимствуют смысл и период из предоставленного чек-листа, но командные подробности — тестовые. Действия наставника не назначаются стажёру. Задачи первого месяца не переносятся в первый день. «Получить доступ» завершается сервисом, «изучить материал» — осознанной отметкой пользователя. Работа в Jira завершается только событием сервиса.

## Интерфейс

Список рабочих контактов слева, личный диалог AI Buddy в центре, компактный маршрут справа. Источник и детали задачи открываются в панели. На узком экране маршрут открывается отдельно. У карточки действия одно однозначное подтверждение; повторный клик блокируется на время запроса. История, карточки и результаты приходят с backend.

Состояния: загрузка, пустая выдача, уточнение, отказ в доступе, ожидание, бизнес-отказ, техническая ошибка, неизвестный результат, успех. Управление доступно клавиатурой, фокус видим, статус не передаётся только цветом. Введённый текст не исчезает при сетевой ошибке. При долгом ответе можно открыть маршрут или источник.

В интерфейсе явно обозначен демонстрационный контур. Управление имитацией отделено от пути стажёра; выдача доступа подписана как тестовое событие владельца ресурса. Прототип не выдаёт себя за настоящий Mattermost или внутренний портал Авито.

## Границы

В первой версии нет собственного SSO, HR-портала, финансовых операций, автоматической переписки с коллегами, обучения на диалогах и произвольного исполнения команд моделью. Вложения добавляются только после отдельной проверки; неработающие элементы управления не показываются.
