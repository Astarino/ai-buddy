# Управляемый выбор инструментов

Запрос пользователя обрабатывает локальная модель. Серверные запреты на секреты и
подмену полномочий действуют до модели. Внешний адаптер сохраняет прежний режим
ответов с отдельным согласием: внутренний агентный контекст наружу не передаётся.

Модель выбирает `get_context`, `search_knowledge`, `prepare_action` или
`prepare_request`; `finish` передаёт типизированный финальный ответ. Первый инструмент получает профиль, маршрут и собственные
операции из доверенного контекста; ID пользователя не является аргументом.
Поиск получает только разрешённые документы. Подготовка использует существующие
контракты и сохраняет точную карточку; инструментов отправки, согласования,
выдачи прав, SQL, shell и произвольных URL у модели нет.

Цикл ограничен шестью ответами модели, восемью инструментами и двумя минутами.
Одинаковые повторные вызовы останавливаются. Типы, неизвестные поля, длины и
допустимые значения проверяются сервером. Результаты возвращаются модели как
данные, без скрытого рассуждения. Ответ ссылается только на найденные источники;
все прочитанные документы входят в зависимости ответа и перепроверяются.

Успешная подготовка карточки останавливает цикл до подтверждения без ещё одного
вызова LLM: текст карточки и факт отсутствия отправки определяет сервер. Сервер исполняет сохранённые
параметры прежним идемпотентным методом. После перезапуска новый запрос получает
сохранённые операции и историю, а незавершённая карточка остаётся доступной.
Изучение руководства подтверждает сам стажёр в панели источника; модель не
ставит эту отметку. После выдачи доступа и изучения можно подготовить назначение.

Given закрытое руководство и отсутствие заявки, when стажёр просит начать работу,
then модель читает контекст и инструкцию и готовит доступ без отправки.
Given pending/approved, then возвращает существующий статус; approved не даёт чтение.
При чтении статуса существующей заявки новый вопрос ответственному не готовится.
Для него нужен явный запрос пользователя либо установленная нехватка сведений.
Given granted и изученное руководство, then готовит первую задачу, требуя подтверждения.
Given отозванный источник, then новый и сохранённый ответы скрывают его содержимое.
Given повтор инструмента, неизвестный инструмент или ошибка модели, then цикл
останавливается без записи в корпоративный сервис; сохранённая карточка доступна.

Проверки: internal/buddy/agent_test.go, internal/model/agent_test.go и отдельный
отчёт настоящей Qwen. Фикстуры проверяют контракт, а не качество модели.

Сервер сообщает доступные типы действий в доверенном контексте; адаптер убирает
недоступные инструменты и сужает enum. Это серверное правило допустимости,
не выбор инструмента вместо модели. При обычном тексте вместо контракта
разрешён один запрос исправить формат. Повторное нарушение не выдаётся
пользователю: статус берётся из сервиса либо тот же адаптер Qwen создаёт
структурированный ответ по найденным источникам. Этот режим отдельно помечен
`agent_status`/`agent_repaired`; он не доказывает соблюдение моделью формата.
