# Модель и данные

Рабочий провайдер — **Qwen3.5 4B через Ollama 0.40.16**. Проверенный вариант
для сдачи работает на Linux CPU без внешнего API-ключа. Веса GGUF Q4_K_M /
llamacpp, размер 3 324 173 934 байта, digest и параметры закреплены в
[model.cpu.lock.json](../model.cpu.lock.json). Нативный MLX-вариант Mac записан
отдельно в [model.lock.json](../model.lock.json): это другие веса и runner.
Название тега само по себе не фиксирует конфигурацию.

Обучения с нуля и fine-tuning нет. Применяется поиск по разрешённым источникам:
проверка прав, полнотекстовое ранжирование и максимум три фрагмента. Вопросы
не ограничены чек-листом; проверенный корпус и инструменты пока относятся
к Backend-примеру. Для другого направления нужны свои данные и проверки.

## Проверенные результаты

Полный [CPU-прогон 43656311396](https://github.com/Astarino/ai-buddy/actions/runs/43656311396)
завершился 15.11.2026 на чистом GitHub Actions ubuntu-24.04 без GPU.
Проверенная в этом прогоне прикладная версия `3d945a0`, промпт `buddy-grounded-v4`, один запрос за раз,
контекст 4096, максимум 512 выходных токенов, temperature 0. Контейнер Ollama
ограничен 6 GiB памяти. После прогона уточнены отображение источников,
короткие запросы следующего шага и ошибки модели, исправлено поведение поля
ввода. Эти изменения проверены отдельными автоматическими тестами; они не
выдаются за повтор всего настоящего модельного набора. Промпт, адаптер и
CPU-конфигурация не изменены.

| Набор | Итог приложения | Настоящие ответы Qwen |
| --- | --- | --- |
| Основной | 50/50 | 21 |
| Отложенный | 9/10 | 10 |
| Регрессия | 1/1 | 1 |
| Практическая ошибка Go | Тесты после уточнения проходят | 2 |

Это **приёмка приложения**, включая серверные workflow, права, поиск и
намеренные сбои. Она не означает 50 правильных генераций модели. Для 18
применимых критериев сырого текста в основном наборе модель прошла 15;
три признания нехватки данных сервер преобразовал в уточнение. Ещё три
inference-случая проверяют права и отзыв во время генерации; для их сырого
текста отдельный критерий не применяется. Отчёты сохраняют исходный ответ,
флаг уточнения, итоговую доставку и фактическое число вызовов.

В H10 отложенного набора модель ответила: «В тестовом корпусе точные команды
настройки отсутствуют, нужно описать цель и безопасный фрагмент ошибки».
Она не поставила `needs_clarification=true`, поэтому критерий не пройден.
Этот промах сохранён, результат не округлён до 100%. Нарушений прав и
неподтверждённых операций в проверенных наборах не обнаружено.

Медиана основного случая с inference — **30,714 с**, диапазон
**18,770–42,895 с**, включая поиск и сохранение. Первый отдельный ответ через
HTTP API занял **42,590 с**. Режим не потоковый: первый содержательный текст
появляется после полного ответа, индикатор ожидания не считается этим временем.
Это замеры конкретного CPU runner-а, не обещание скорости на любом устройстве.

Практическая проверка действительно загрузила официальную Go-документацию,
передала фрагменты Qwen и выполнила фиксированный тест в изолированном проекте.
Первый ответ был общим, после вопроса о конкретной папке модель назвала
`workspace/hello`. Смена каталога исправила запуск. Оба ответа заняли 75,516 с
суммарно. У модели нет shell; проверяющий код выполнял заранее заданную
безопасную команду, а не произвольный текст генерации.

## Границы модели и серверной логики

Модель получает краткий вопрос, допустимый контекст и временные `source-1…3`.
В payload документов не включаются внутренние ID ресурсов, ACL, hash и сырые
адреса загрузки. JSON-схема ограничивает цитаты этими ID, сервер проверяет
результат и повторно проверяет права и версии перед сохранением.

Неполный вопрос и конфликт источников могут привести к серверному уточнению
до inference. Явно названный публичный документ показывается как выдержка,
код Jira-проекта извлекается из разрешённой командной инструкции. Эти ответы
имеют `kind=source` и не объявляются модельной генерацией. Ограниченная проверка
признанной нехватки сведений может заменить ответ на уточнение и записать
`answer_guarded` в аудит. Она не проверяет истинность любого утверждения.

Модель не получает SQL, shell, секреты сервисов или произвольные сетевые адреса.
Действия исполняет Go после проверки пользователя, прав и точного подтверждения.
Факты обновляются через документы, полномочия не зависят от формулировки промпта.

## Запуск на CPU

С установленным Docker Compose:

```sh
sh scripts/jury.sh --check
sh scripts/jury.sh --model
```

Первый запуск загружает около 3,3 ГБ весов в отдельный том; для образов,
базы и сборки нужны дополнительные диск и память. GPU и API-ключ не нужны.
Ollama не публикуется наружу. На CPU веса удерживаются до 300 секунд между
ответами внутри контейнера; это уменьшает повторную загрузку. Инструкции
по остановке и профилям — в [submission.md](submission.md).

Workflow `CPU model verification` дополнительно запускает основной, отложенный,
регрессионный наборы и практический Go-диалог. Артефакты содержат runtime,
фактический digest, ответы, время и commit. Обычный CI использует fixture и
не выдаётся за оценку настоящей Qwen.

## Нативный запуск и память Mac

На M4 с 16 GiB согласованная повторная попытка остановлена watchdog при 23%
свободной памяти, до ответа. После остановки память восстановилась до 56%;
сторонние приложения не закрывались и новые веса не скачивались.
[Запись попытки](../reports/attempts/model-acceptance-m4-memory-stop.json)
не является приёмкой качества текущей модели. Поэтому основное воспроизведение
сдачи — проверенный CPU-вариант, а видео использует сохранённый CPU-ответ.

При пользовательском тестировании 15.11 защита вновь остановила runtime на 22%.
После разрешённого закрытия Safari один настоящий ответ через приложение
успешно получен за 7,659 с: Grafana относится к первому месяцу. Веса после
ответа выгружены. Это ограниченный smoke-тест, не повтор полного набора и не
обещание такой задержки при любой нагрузке. Запуск требует достаточной
свободной памяти; порог защиты остаётся 25%.

Для отдельно согласованного нативного запуска нужен официальный
[Ollama 0.40.16](https://github.com/ollama/ollama/releases/tag/v0.40.16):

```sh
sh scripts/ollama.sh
```

Скрипт включает `OLLAMA_NO_CLOUD=1`, loopback, один запрос и контекст 4096.
Он не загружает веса автоматически. `OLLAMA_BIN` задаёт путь к бинарнику;
установленные веса проверяются по `/api/tags` и lock-файлу. Нативный запрос
выгружает модель после ответа (`keep_alive=0`). На macOS launcher раз в секунду
проверяет `memory_pressure` и останавливает только свой runtime ниже 25%.
Это дополнительный ограничитель, не гарантия отсутствия давления на память.
Автоматического перезапуска нет. Модель 9B не проверялась и не загружается.

На этой машине Homebrew-сборка 0.40.16 возвращала HTTP 501 для MLX structured
output из-за отсутствующей `libollama_xgrammar.dylib`. Официальный архив той же
версии её содержит. Это результат конкретной проверки, не утверждение обо
всех версиях Homebrew. Неподдержанный формат не скрывается обходом валидации.

## Другие провайдеры и история

- `MODEL_PROVIDER=ollama`: явно заданные `MODEL_BASE_URL` и `MODEL_NAME`.
  При сбое текст не отправляется другому провайдеру.
- `MODEL_PROVIDER=compatible`: выбранный API формата chat completions,
  `MODEL_BASE_URL` с `/v1`, `MODEL_NAME`, `MODEL_API_KEY` на сервере.
  Внешний адрес требует `ALLOW_EXTERNAL_MODEL=true`, HTTP разрешён только
  для локального адреса. Совместимость формата не доказывает качество модели.
- `MODEL_PROVIDER=fixture`: помеченные фиксированные ответы без inference.
  Позволяет проверить приложение и операции, не доказывает работу Qwen.

Для внешнего inference нужно подтверждение конкретного вопроса. Передаются
только разрешённые публичные фрагменты; история, профиль и внутренние данные
удаляются. Автоматического внешнего fallback нет. Реальный провайдер и контур
требуют отдельной проверки условий обработки данных. Ключа в комплекте нет.

Неудачные прогоны сохранены в `reports/history/`: v3 CPU дал 46/50 и неверный
совет в Go-примере; ранний v4 — 42/50. Отдельный прогон правильно назвал папку,
но тест не учёл синоним «директория»; исходный результат также сохранён.
После этого проверены компактный контекст, временные ID источников, уточнения
и явные серверные операции. Исторические v2-замеры Mac не подменяют текущую
приёмку. Дообучение не проводилось.
