# Модель и данные

Первая конфигурация: локальная **Qwen3.5 4B**, Ollama 0.40.16, Apple M4, 16 GiB. Точный digest, вариант весов и параметры находятся в [model.lock.json](../model.lock.json). Название тега само по себе не фиксирует веса.

Используется RAG по небольшому корпусу: сначала ACL и полнотекстовое ранжирование, затем максимум три разрешённых документа. Обучения с нуля и fine-tuning нет. Изменение фактов происходит через документы; права и исполнение действий остаются в Go. У модели нет инструментов с побочными эффектами. Серверный workflow обрабатывает подготовку и подтверждение операций.

## Локальный запуск

Установи официальный [Ollama](https://ollama.com/download). Для воспроизведения этой проверки нужна версия 0.40.16; [релиз и архивы](https://github.com/ollama/ollama/releases/tag/v0.40.16). Перед загрузкой оставь место для примерно 4 ГБ весов, runtime, зависимостей и свободного пространства системы.

```sh
sh scripts/ollama.sh
```

В другом терминале:

```sh
ollama pull qwen3.5:4b
ollama list
```

`scripts/ollama.sh` включает `OLLAMA_NO_CLOUD=1`, loopback, один запрос, один загруженный экземпляр и контекст 4096. `OLLAMA_BIN` позволяет указать путь к официальному бинарнику. Скрипт не скачивает веса и не запускает модель при старте приложения. После каждого ответа веса выгружаются. Это увеличивает задержку, зато не удерживает память Mac между вопросами. Для немедленной выгрузки: `ollama stop qwen3.5:4b`.

Проверь `GET /api/version` и `GET /api/tags` локального Ollama и сравни с lock-файлом. На другой архитектуре Ollama может выбрать другой runner и вариант весов; это отдельная конфигурация, которую нужно проверить и записать. 9B на этой машине не проверялась и автоматически не загружается.

На macOS launcher раз в секунду проверяет `memory_pressure` и останавливает только запущенный им Ollama, если свободный процент падает ниже `OLLAMA_MIN_FREE_MEMORY_PERCENT` (по умолчанию 25). Это дополнительное ограничение разработки, а не гарантия отсутствия давления на память. Модель не перезапускается автоматически. На Linux этот macOS-датчик не применяется.

При совместной записи браузерного видео и inference лимит сработал на 22% между замерами. Runtime был остановлен, память восстановилась; сторонние приложения не закрывались. Поэтому в демонстрационном видео показан сохранённый ответ настоящей Qwen, а действия записаны вживую без одновременной загрузки весов. Полный модельный набор выполнялся отдельно.

### Ограничение Homebrew-сборки

На проверенной машине Homebrew-сборка 0.40.16 отвечала HTTP 501 `structured output is unavailable` для MLX: в поставке отсутствовала `libollama_xgrammar.dylib`. Официальный архив той же версии содержит её; после замены runtime JSON-схема заработала с теми же весами. Не скрываем 501 переходом к непроверенному формату. Это результат конкретной проверки сборок, а не утверждение обо всех версиях Homebrew.

## Измерения

Результаты ниже получены 11.11.2026 для `buddy-grounded-v2`. Полный CPU-прогон v3 дал 46/50 на основном наборе, 10/10 на отложенном и 1/1 на регрессии. Нарушений прав не обнаружено, но практический пример Go завершился неверным советом, поэтому весь workflow не принят. Исходные отчёты сохранены в `reports/history/qwen-v3-cpu/`. Текущий промпт v4 уточняет применение документации к описанной ситуации и использует компактный контекст с временными ID. Его новый настоящий прогон ещё не завершён; старые результаты не являются его приёмкой.

Ранний smoke проводился с keep_alive=30s. На первом длинном прогоне память накапливалась между запросами; watchdog остановил runtime при 21% свободной памяти. Рабочая конфигурация изменена на keep_alive=0.

Три последовательных вопроса по инструкции доступа дали корректный JSON и верные факты. По метрикам Ollama: первый запрос 7,876 с, включая загрузку 2,511 с; два тёплых — 2,346 с и 2,120 с. Полный вопрос из веб-клиента через backend и поиск занял 6,033 с. Режим пока не потоковый: первый содержательный текст появляется после полного ответа. Индикатор ожидания не считается временем ответа модели.

Локальный watchdog останавливал бы наш runtime при падении `memory_pressure` ниже 25% свободной памяти. На раннем smoke минимум был 33%, в пробном пути приложения — 29%, на итоговом наборе — 30%; после ответов модель выгружалась. Показатель `memory_pressure` не равен RSS процесса. Это не универсальные требования к устройству и не гарантия задержки.

Итоговая инженерная приёмка: **50/50 случаев**, из них **26 настоящих вызовов inference**, без нарушения прав или неподтверждённых операций. Остальные случаи проверяют серверные workflow и намеренные сбои. Время случая с inference: медиана **6,505 с**, диапазон **4,917–8,429 с**, включая поиск, запись и загрузку весов. Отчёт: [model-evaluation.json](../reports/model-evaluation.json).

На небольшом отложенном наборе — **9/10**. В H08 модель вместо общего чек-листа выбрала допустимые факты из Backend-чек-листа. Добавлено явное ограничение поиска при просьбе о конкретном чек-листе; отдельная регрессия H08 прошла, основной набор повторён. Исходный результат 9/10 сохранён в [model-holdout.json](../reports/model-holdout.json), исправление — в [model-regression.json](../reports/model-regression.json). Проверка автоматически искала ожидаемые факты и источники; она не заменяет экспертную оценку всех формулировок и не даёт оснований обещать 100% точность.

### Уточнение поведения после CPU-прогонов

Первый v4-прогон: 42/50, 10/10 и 1/1, без нарушений прав. Сохранились отказы
назвать имеющийся код проекта и декларативные ответы вместо уточнения.
Сырые результаты — в `reports/history/qwen-v4-core/`. В Go-диалоге после
уточнения модель назвала `workspace/hello`; тест не учёл слово «директория»
и ошибочно отклонил ответ. Этот исход также сохранён, критерий исправлен
без изменения ожидаемой папки.

Сервер отдельно обрабатывает неполные вопросы, извлекает код проекта из
разрешённого документа и показывает выдержку по явно названному публичному
источнику. Признанную моделью нехватку данных он превращает в уточнение,
сохраняя аудит срабатывания. Это не универсальная проверка истинности.
Инженерная приёмка оценивает итоговое поведение приложения; число inference,
сырой ответ модели и способ доставки сохраняются отдельно. Приёмка этой
политики настоящей моделью ещё ожидается.

## Переносимость и проверка без GPU

14.11.2026 настоящий Qwen запущен в GitHub Actions на Linux без GPU:
контейнер Ollama с лимитом 6 GiB вернул через API приложения правильный ответ
о периоде изучения Grafana за 63,895 с. Это один холодный ответ, не полная
приёмка. Linux использует GGUF Q4_K_M / llamacpp и другой digest, чем MLX
на Mac; конфигурация зафиксирована в `model.cpu.lock.json`.

Повтор текущего v3-набора на Mac остановлен watchdog при 23% свободной памяти
до первого ответа. Память восстановилась до 56%, сторонние приложения не
закрывались. [Запись попытки](../reports/attempts/model-acceptance-m4-memory-stop.json)
не является оценкой качества модели. Исторические v2-отчёты сохранены в
`reports/history/qwen-v2/`. Новый harness сохраняет также неудачный/неполный
прогон и различает попытки inference и валидные ответы.

Ручной workflow `CPU model verification` проверяет 50 приёмочных, 10
отложенных, одну регрессию и реальную ошибку Go с загрузкой официальных
документов. Для него модель удерживается до 300 секунд между ответами внутри
контейнера с лимитом памяти; нативный режим Mac по-прежнему выгружает её сразу.
Итог полного CPU-прогона добавляется только после фактической проверки.

- `MODEL_PROVIDER=ollama`: настоящий локальный или серверный Ollama, `MODEL_BASE_URL`, `MODEL_NAME`. Текст приложения при сбое не отправляется другому провайдеру.
- `MODEL_PROVIDER=compatible`: явно выбранный HTTP API формата chat completions, `MODEL_BASE_URL` с `/v1`, `MODEL_NAME`, `MODEL_API_KEY`. Для внешнего адреса обязательно `ALLOW_EXTERNAL_MODEL=true`; HTTP разрешён только для локальных адресов. Совместимость формата не доказывает качество другой модели. Собственный внешний ключ в комплект не входит.
- `MODEL_PROVIDER=fixture`: фиксированный тестовый провайдер для проверки приложения без модели. Интерфейс и ответы явно помечены. Этот режим не доказывает работу Qwen.

В прототипе все командные документы синтетические. Для настоящего внедрения внешний провайдер требует отдельного решения по данным и контуру. Локальная модель на компьютере автора не обеспечивает доступность жюри: нужен доступный inference-сервер либо устройство, соответствующее инструкции. Режим fixture позволяет проверить операции, права и сохранение, но оценка ИИ выполняется с настоящей моделью.
