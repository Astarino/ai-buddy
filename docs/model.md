# Модель и данные

Первая конфигурация: локальная **Qwen3.5 4B**, Ollama 0.40.16, Apple M4, 16 GiB. Точный digest, вариант весов и параметры находятся в [model.lock.json](../model.lock.json). Название тега само по себе не фиксирует веса.

Используется RAG по небольшому корпусу: сначала ACL и полнотекстовое ранжирование, затем максимум три разрешённых документа. Обучения с нуля и fine-tuning нет. Изменение фактов происходит через документы; права и исполнение действий остаются в Go. У модели нет инструментов с побочными эффектами. Серверный workflow обрабатывает подготовку и подтверждение операций.

## Локальный запуск

Установи официальный [Ollama](https://ollama.com/download). Для воспроизведения этой проверки нужна версия 0.40.16; [релиз и архивы](https://github.com/ollama/ollama/releases/tag/v0.40.16). Перед загрузкой оставь место для примерно 4 ГБ весов, runtime, зависимостей и свободного пространства системы.

```sh
sh scripts/ollama.sh
```

В другом терминале:

```sh
ollama pull qwen3.5:4b
ollama list
```

`scripts/ollama.sh` включает `OLLAMA_NO_CLOUD=1`, loopback, один запрос, один загруженный экземпляр и контекст 4096. `OLLAMA_BIN` позволяет указать путь к официальному бинарнику. Скрипт не скачивает веса и не запускает модель при старте приложения. После каждого ответа веса выгружаются. Это увеличивает задержку, зато не удерживает память Mac между вопросами. Для немедленной выгрузки: `ollama stop qwen3.5:4b`.

Проверь `GET /api/version` и `GET /api/tags` локального Ollama и сравни с lock-файлом. На другой архитектуре Ollama может выбрать другой runner и вариант весов; это отдельная конфигурация, которую нужно проверить и записать. 9B на этой машине не проверялась и автоматически не загружается.

### Ограничение Homebrew-сборки

На проверенной машине Homebrew-сборка 0.40.16 отвечала HTTP 501 `structured output is unavailable` для MLX: в поставке отсутствовала `libollama_xgrammar.dylib`. Официальный архив той же версии содержит её; после замены runtime JSON-схема заработала с теми же весами. Не скрываем 501 переходом к непроверенному формату. Это результат конкретной проверки сборок, а не утверждение обо всех версиях Homebrew.

## Что измерено на раннем smoke

Ранний smoke проводился с keep_alive=30s. На первом длинном прогоне память накапливалась между запросами; watchdog остановил runtime при 21% свободной памяти. Рабочая конфигурация изменена на keep_alive=0. Задержки ниже относятся к ранней конфигурации; итоговый набор измеряется заново.

Три последовательных вопроса по инструкции доступа дали корректный JSON и верные факты. По метрикам Ollama: первый запрос 7,876 с, включая загрузку 2,511 с; два тёплых — 2,346 с и 2,120 с. Полный вопрос из веб-клиента через backend и поиск занял 6,033 с. Режим пока не потоковый: первый содержательный текст появляется после полного ответа. Индикатор ожидания не считается временем ответа модели.

Локальный watchdog останавливал бы наш runtime при падении `memory_pressure` ниже 25% свободной памяти. На smoke минимум был 33%, в пробном пути приложения — 29%; затем модель выгружена. Показатель `memory_pressure` не равен RSS процесса. Это не универсальные требования к устройству и не гарантия задержки. Итоговый набор и результаты описываются отдельно после прогона.

## Переносимость и проверка без GPU

- `MODEL_PROVIDER=ollama`: настоящий локальный или серверный Ollama, `MODEL_BASE_URL`, `MODEL_NAME`. Текст приложения при сбое не отправляется другому провайдеру.
- `MODEL_PROVIDER=compatible`: явно выбранный HTTP API формата chat completions, `MODEL_BASE_URL` с `/v1`, `MODEL_NAME`, `MODEL_API_KEY`. Для внешнего адреса обязательно `ALLOW_EXTERNAL_MODEL=true`; HTTP разрешён только для локальных адресов. Совместимость формата не доказывает качество другой модели. Собственный внешний ключ в комплект не входит.
- `MODEL_PROVIDER=fixture`: фиксированный тестовый провайдер для проверки приложения без модели. Интерфейс и ответы явно помечены. Этот режим не доказывает работу Qwen.

В прототипе все командные документы синтетические. Для настоящего внедрения внешний провайдер требует отдельного решения по данным и контуру. Локальная модель на компьютере автора не обеспечивает доступность жюри: нужен доступный inference-сервер либо устройство, соответствующее инструкции. Режим fixture позволяет проверить операции, права и сохранение, но оценка ИИ выполняется с настоящей моделью.
