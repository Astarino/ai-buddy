## Запустить настоящую модель

Нужен Docker с Compose, интернет для первой загрузки и достаточно памяти
для Ollama, базы и приложения. Проверенный CPU-вариант ограничивает Ollama
6 GiB, использует контекст 4096 и обрабатывает один запрос за раз.
Linux-веса Qwen занимают около 3,3 ГБ, EmbeddingGemma — 622 МБ; для образов и сборки нужен дополнительный диск.
API-ключ и GPU не нужны. Первый ответ может занять около минуты.

```sh
sh scripts/jury.sh --check
sh scripts/jury.sh --model
```

Открой `http://localhost:8090`. Выбери Антона или Ирину.
Другой порт: `BUDDY_PORT=8092 sh scripts/jury.sh --model`.
Для остановки с сохранением данных и весов:

```sh
docker compose -f compose.yaml -f compose.cpu.yaml down
```

`sh scripts/jury.sh` без параметров запускает помеченный fixture-режим.
Он позволяет проверить интерфейс, права и операции без загрузки модели.
Его ответы не являются доказательством работы Qwen. Нативный запуск,
версии и дополнительная настройка описаны в [run.md](run.md).

## Что проверить в интерфейсе

1. Главный запрос о недоступной документации; открой источник и проверь карточку.
2. Подтверди заявку. Алексей согласует, затем отдельно выдаёт доступ.
3. Антон изучает руководство и подтверждает назначение CAT-101.
4. Обнови страницу: номер и результат сохраняются без повторной операции.
5. Спроси о готовности к ревью и открой применимый источник.
6. Дополнительно подготовь вопрос наставнику, проверь адресата и подтверди.
   Даша отвечает со своей вкладки; личная переписка туда не копируется.

Точные реплики и чистый seed — [demo.md](demo.md), [run.md](run.md).

## Автоматические доказательства

Для разработки: `make test`, `make coverage`, `make e2e` с отдельной
PostgreSQL. Настоящий сетевой поиск включается `RUN_LIVE_BROWSER=true make e2e`.
Методика покрытия и связь SDD с тестами — в [testing.md](testing.md).

Текущий ручной workflow `Agent and hybrid search` запускает настоящую Qwen
и EmbeddingGemma на Linux CPU: [7/7 решений и состояний](../reports/agent-qwen.json),
[прогон](https://github.com/Astarino/ai-buddy/actions/runs/43844812208).
Поиск отдельно сравнен на 26 вопросах; [отчёт](../reports/retrieval.json) явно
показывает малый корпус и отсутствие доказанного общего выигрыша.
Покрытие строк: backend 85,62%, frontend 88,13%; 14 браузерных проверок.

Версии и digest: `model.cpu.lock.json`, `model.lock.json`, `embedding.lock.json`.
Старый workflow `CPU model verification` и 50 grounded-случаев относятся к предыдущему
адаптеру; они не подменяют текущую проверку native tool calling.

## Границы прототипа

AI Buddy рассчитан на разные направления. В этой версии проверен Backend-набор:
две команды, их маршрут и источники. Для другого направления нужны применимые
материалы и собственная проверка качества. Вопросы не ограничены чек-листом.

Внутренние правила, профили, доступы и Jira синтетические; HTTP-сервис имитирует
корпоративные операции. Поиск действительно загружает официальную документацию
Go и Git по фиксированным адресам. Произвольного интернет-поиска и выполнения
shell-команд моделью нет. Настоящие Mattermost, Jira, Confluence и MCP пока
не подключены. Требования к целевому внедрению и реализованные границы
разделены в [architecture.md](architecture.md).

Живой пользовательский пилот не проводился, экономия времени не заявляется.
План проверки — [metrics.md](metrics.md). Финальная отправка на платформу
выполняется после выбора и фиксации комплекта.
