# Контракты

Основной API доступен по `/api`. Тело мутаций — JSON; неизвестные поля и лишние JSON-объекты отклоняются. Сессия хранится в HttpOnly cookie. `X-Buddy-Context` защищает вкладку от незаметной смены тестового профиля в другой вкладке: при несовпадении возвращается 409. Это не источник полномочий — личность по-прежнему определяется cookie на сервере.

| Метод и путь | Вход | Результат |
| --- | --- | --- |
| `GET /bootstrap` | — | доступные синтетические профили и конфигурация модели |
| `POST /session` | `profile_id: anton/irina` | тестовая сессия, cookie |
| `DELETE /session` | `{}` | завершение сессии |
| `GET /state` | сессия | история, маршрут, разрешённый каталог, карточки и собственные операции |
| `POST /messages` | `id, text` | сохранённый ответ; повтор ID с тем же текстом не дублирует сообщение |
| `GET /documents/{id}` | сессия | текст, происхождение, версия, тестовая маркировка; 404 для недоступного |
| `POST /actions` | `kind: access/issue`, `reason` | карточка с неизменяемыми серверными параметрами, ID и сроком 15 минут |
| `POST /actions/{id}/confirm` | `{}` | результат сервиса; точный ID, ресурс и бизнес-статус |
| `POST /tasks/{id}/complete` | `{}` | самоотчёт по доступному шагу, затем актуальное состояние |
| `POST /refresh` | `{}` | фактические операции и обновлённые права/маршрут |
| `POST /draft` | `question` или пустая строка | сохранённый черновик наставнику без отправки |
| `GET /diagnostics` | сессия | события своей сессии, версия промпта и имя модели, без промптов и ключей |
| `POST /demo/events` | `key, status`, `X-Demo-Token` | тестовое событие владельца ресурса |
| `GET /demo/metrics` | `X-Demo-Token` | технические счётчики без текстов переписки |

Действия доступа всегда относятся к пространству своей команды и чтению. Первая задача всегда относится к `CAT-101` либо `DLV-101`. Клиент не передаёт произвольный ресурс, согласующего, роль, URL или SQL. Реальная отправка начинается только после подтверждения сохранённой карточки.

Ошибка: `{code, message}`. Используются 400 (ввод), 401 (нет сессии), 403 (права/зависимость), 404 (объект недоступен), 409 (конфликт), 410 (истёкшее подтверждение), 429 (занята модель), 503 (модель/сервис не ответили). Техническое состояние не заменяет бизнес-статус операции.

## Имитация корпоративного сервиса

Отдельный процесс, по умолчанию `127.0.0.1:8091`. Сервисный `Authorization: Bearer <CORPORATE_TOKEN>` требуется для операций; события используют отдельный `DEMO_OPERATOR_TOKEN`.

`POST /operations` получает `{user_id, action}`. `action` содержит ID идемпотентности, `kind`, точный ресурс, уровень и обоснование. Сервис повторно проверяет каталог, владельца и совпадение параметров при повторе. Возвращает `Operation` из `internal/buddy/types.go`: `id, key, user_id, kind, resource, level, reason, status, note, updated_at`.

`GET /operations?user=<trusted-id>` возвращает только операции выбранного доверенным backend пользователя. Этот API не публикуется браузеру. Стажёр не может выбрать чужой ID в основном API.

`POST /events` получает `{user_id, key, status}` от тестового оператора. Допустимы `pending → approved → granted`, `pending/approved → rejected`, `granted → revoked`; для Jira — `assigned → done`. Повтор того же события идемпотентен. Удаление ресурса, merge и production-действия отсутствуют.

Для демонстрации сбоев событие с пустым `key` выбирает режим своего пользователя: `normal`, `unavailable`, `lost_response`. Последний сохраняет операцию, но задерживает ответ за пределами тайм-аута клиента. Настоящий результат восстанавливается по прежнему ключу, без новой заявки.
