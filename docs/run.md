# Запуск и настройка

Проверенная нативная среда: macOS, Apple M4, 16 GiB, Go 1.25.5, Node 25.9.0,
pnpm 10.16.0, PostgreSQL 16.14, Python 3.14. Python нужен проверочным скриптам;
прикладной backend написан на Go.

## Нативно

Запусти PostgreSQL, создай базы `ai_buddy` и `ai_buddy_test`, скопируй
`.env.example` в `.env`. Пример использует Unix socket `/tmp`; при другом
размещении укажи PostgreSQL URI в `DATABASE_URL` и `TEST_DATABASE_URL`.

```sh
make setup
make dev
```

Команда собирает frontend и оба Go-процесса. Приложение слушает 127.0.0.1:8090,
имитация — 127.0.0.1:8091. Ctrl+C останавливает эти процессы, данные остаются в
PostgreSQL. После изменения Go перезапусти команду; после изменения UI пересобери
`pnpm --dir web build` и обнови страницу. Для HMR есть `pnpm --dir web dev` с
проксированием `/api` на backend.

Модель не запускается автоматически. В отдельном терминале выполни `make model`
с официальным Ollama, затем явно загрузи `qwen3.5:4b`. `OLLAMA_BIN` в `.env`
позволяет указать бинарник. [Digest, параметры и ресурсы](model.md).

## Docker

```sh
docker compose --env-file .env.docker.example up --build
```

Состав: PostgreSQL, отдельная имитация и Go-приложение со статическим React.
Публикуется только порт приложения на loopback. Данные остаются в именованном
томе. `docker compose down` останавливает процессы; флаг `-v` удаляет данные и
не нужен для обычного завершения. Для второй копии используй `BUDDY_PORT=8092`.

По умолчанию включён явный `fixture` без LLM. Для реальной модели скопируй
`.env.docker.example` в игнорируемый `.env.docker` и задай:

```dotenv
DOCKER_MODEL_PROVIDER=ollama
DOCKER_MODEL_BASE_URL=http://host.docker.internal:11434
DOCKER_MODEL_NAME=qwen3.5:4b
```

Запуск: `docker compose --env-file .env.docker up --build`. На Docker Desktop
`host.docker.internal` ведёт на хост. На Linux loopback хоста обычно недоступен
из bridge-сети: нужен согласованный внутренний URL inference или отдельная
настройка сети. Не публикуй Ollama в интернет ради проверки. Внешний совместимый
API выбирается явно и требует отдельного разрешения передачи и своего ключа.

## Переменные backend

Внешний провайдер требует одновременно `ALLOW_EXTERNAL_MODEL=true` и
`MODEL_DATA_POLICY=public-only`. Интерфейс запрашивает подтверждение конкретного
вопроса. Внутренние источники не отправляются; автоматического fallback нет.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | PostgreSQL URI, только сервер |
| `APP_MODE` | `demo` по умолчанию; `corporate` включает OIDC и ресурсную авторизацию |
| `APP_ADDR`, `CORPORATE_ADDR` | адреса двух процессов |
| `CORPORATE_BASE_URL` | endpoint корпоративного адаптера |
| `CORPORATE_TOKEN` | сервисная авторизация имитации |
| `DEMO_OPERATOR_TOKEN` | полномочие тестового оператора; пустое значение блокирует события |
| `MODEL_PROVIDER` | `ollama`, `compatible`, `fixture` |
| `MODEL_BASE_URL`, `MODEL_NAME` | явный endpoint и модель |
| `MODEL_API_KEY` | ключ внешнего провайдера, никогда не frontend |
| `ALLOW_EXTERNAL_MODEL` | `true` при осознанном выборе внешнего inference |
| `MODEL_DATA_POLICY` | `internal` по умолчанию; `public-only` для одобренного внешнего провайдера |
| `SECURE_COOKIE` | `true` при размещении за HTTPS |
| `WEB_DIR` | собранный frontend, по умолчанию `web/dist` |

В Compose настройки модели имеют префикс `DOCKER_`: нативный `.env` с 127.0.0.1
не направляет контейнер к самому себе. Токены из примеров — синтетические
тестовые данные, а не production-секреты.

Вход: `anton` / Антон Соколов / Каталог и `irina` / Ирина Белова / Доставка.
Пароли не нужны: этот вход имитирует корпоративную идентичность, не заменяя SSO.

## Восстановление

- Проверь PostgreSQL URI и доступность базы. Идемпотентная схема создаётся при
  старте; существующие данные не очищаются.
- Проверь порт 8091 и одинаковый `CORPORATE_TOKEN`. При сбое закрытые материалы
  скрываются, интерфейс остаётся доступным.
- Для модели проверь официальный runtime, `/api/tags` и точный тег. Ошибка
  MLX 501 разобрана в `model.md`; неправильный JSON не считается успехом.
- После потерянного ответа обнови состояние. Повтор подтверждения использует
  прежний ключ, результат не дублируется.
- После демонстрации недоступности выбери в пульте «Обычный режим».
- `make e2e` создаёт временную схему и отдельные серверы, сохраняя рабочую базу.

Для настоящего корпоративного размещения нужны доверенная идентичность,
адаптеры сервисов, TLS и согласованный контур данных. `.env` и ключи не входят в Git.

## Подключение корпоративного контура

Шаблон — `.env.corporate.example`, схема каталога —
`examples/corporate-catalog.json`. Оба содержат примеры, не рабочие реквизиты.
Нужны зарегистрированное OIDC-приложение, каталог с issuer/subject и точными
ресурсами, сервис авторизации по [контракту](api.md), адаптер операций,
согласованный inference и HTTPS перед приложением. Переменные остаются на
сервере: `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`,
`OIDC_REDIRECT_URL`, `AUTHORIZATION_BASE_URL`, `AUTHORIZATION_TOKEN`, `CATALOG_FILE`.
Если token/JWKS endpoint расположен на другом origin, его нужно явно включить в
`OIDC_TRUSTED_ORIGINS`. Redirect URL — адрес `/api/login/callback` нашего приложения.

Схему из `internal/storage/schema.sql` применяет отдельная роль миграций.
Корпоративный runtime открывает уже подготовленную схему без DDL; его роль имеет
SELECT/INSERT для `buddy_audit` без UPDATE/DELETE. Для остальных таблиц нужны
права, соответствующие операциям приложения; роль не должна владеть схемой.
Устанавливаются политика хранения/удаления, ротация ключей и ограничения сети.
Нужна отдельная база; старые демо-диалоги не присваиваются корпоративному субъекту.

После загрузки окружения запускается только `go run ./cmd/server` либо собранный
бинарник. `make dev` запускает демонстрацию с имитацией и для этого режима не
предназначен. `DEMO_OPERATOR_TOKEN` должен быть пустым, `SECURE_COOKIE=true`;
fixture и демо-токен запрещены. TLS завершается на согласованном reverse proxy,
прямой доступ к HTTP-порту приложения закрывается. При отсутствии обязательной
настройки приложение завершает запуск с ошибкой.

Каталог — версионный файловый снимок, загружаемый при старте. Изменения требуют
нового снимка и перезапуска; это не работающий коннектор Confluence. Права
проверяются заново через Authorizer. Регистрация реальных сервисов, обновление
индекса, ротация и эксплуатационная проверка остаются работой целевого внедрения.
Подробности и приёмка — в [спецификации интеграций](../specs/integrations.md).
