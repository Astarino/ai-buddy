# Речь к 11 слайдам

1. **AI Buddy.** Помощник для стажёра в личном рабочем диалоге. Сначала смотрим
   PDF и короткое видео, затем запускаем приложение по README. Репозиторий публичный;
   общедоступный сервер не развёрнут, localhost не выдаём за публичную ссылку.

2. **Рабочая проблема.** Организаторы примерно оценивали выход на первую задачу
   в две недели, участие наставника — в пять часов в неделю. Это исходные ориентиры,
   не измеренная экономия нашего продукта. Проверяем конкретный барьер: нет документации.

3. **Один диалог.** Стажёр видит источник, точное действие и ближайший шаг в контексте
   рабочей цели. Маршрут помогает продолжить, а наставник остаётся участником процесса.

4. **Выбор и проверка.** Qwen выбирает инструменты чтения и подготовки. Go получает
   доверенную идентичность, проверяет права и параметры. Отправить заявку модель
   не может: пользователь подтверждает сохранённую карточку с конкретным ресурсом.

5. **Два события.** Согласованная заявка ещё не даёт доступа. Только отдельная выдача
   владельцем открывает защищённое руководство. Повторный вопрос не создаёт дубль.

6. **Продолжение.** После изучения руководства buddy готовит первую подходящую задачу.
   Подтверждение вызывает имитацию Jira, CAT-101 сохраняется после обновления.
   Назначение не означает выполнения; код и ревью остаются работой людей.

7. **Знания для работы.** Здесь настоящий ответ Qwen о критериях ревью и открытый
   источник. Нет надёжного материала — уточняем или готовим подтверждаемый вопрос
   наставнику. Синтетические инструкции не называем регламентами Авито.

8. **Архитектура.** React оставляет интерфейс доступным во время ожидания, Go
   хранит правила и ограничивает цикл, PostgreSQL сохраняет операции и аудит.
   HTTP-имитация позволяет проверить интеграционные контракты. Настоящие
   Mattermost, Jira и Confluence потребуют согласованных адаптеров и прав.

9. **Поиск измерен.** Сравнили прежний поиск, BM25, embeddings и hybrid на 26 вопросах.
   ACL-утечек не обнаружено. Hybrid дал 100% Recall@5 и 89,1% MRR@10, но разница
   с прежним MRR меньше одного пункта. Общий выигрыш на таком корпусе не доказан;
   сохраняем явный BM25 fallback и расширяем проверку перед внедрением.

10. **Доказательства версии.** Семь сценариев настоящей Qwen на CPU прошли отдельно
    по модельному выбору и состоянию приложения. Покрытие строк backend 85,62%,
    frontend 88,13%; 14 браузерных проверок. Это инженерная приёмка на синтетике,
    не независимая оценка универсальной точности и не пилот на стажёрах.

11. **Результат рабочего пути.** Источник найден, доступ получен, первая задача
    назначена. Предлагаем жюри повторить путь по README: репозиторий содержит
    инструкции запуска без GPU, тестовые профили и проверки. Для оценки эффекта
    на стажёрах подготовлена отдельная методика пилота в docs/metrics.md.

## Короткие ответы

- GPU и ключ жюри не требуются: есть закреплённый Docker CPU-профиль.
- 27B не загружалась; крупная модель требует отдельного сравнения и ресурсов.
- Модель не получает SQL, shell, полномочия согласующего или произвольную сеть.
- Фикстуры отмечены отдельно и не доказывают inference.
- Push в GitHub не заменяет загрузку последнего комплекта в личный кабинет конкурса.
